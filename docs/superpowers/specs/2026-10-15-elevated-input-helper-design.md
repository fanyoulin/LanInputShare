# LanInputShare 高权限输入助手设计

日期：2026-10-15

## 背景与目标

LanInputShare 客户端当前以普通完整性级别运行，并通过 `SendInput` 注入远端鼠标和键盘。当客户端前台程序以管理员权限运行时，Windows UIPI 可能静默丢弃这些注入事件。实机已复现：网络连接和输入消息均正常，`SendInput` 返回成功，但高完整性任务管理器前台的光标不移动；客户端物理鼠标不受该限制。

本次改动的目标是：

- 客户端可控制任务管理器、管理员命令行、管理员安装或卸载窗口等高完整性普通桌面程序；
- 用户只在首次启用或修复助手时确认一次 UAC，日常启动不重复弹窗；
- 主控端和客户端主程序继续以普通权限运行；
- 高权限组件只拥有输入注入职责，不承载网络、剪贴板、文件传输或界面逻辑；
- 助手不可被普通本地进程当作通用提权输入代理滥用；
- 助手不可用时，普通窗口控制和紧急返回能力仍然可用，并向用户明确显示降级状态。

## 明确边界

本功能支持默认交互桌面上的普通和高完整性窗口，但不承诺控制以下界面：

- 屏幕变暗后的 UAC 安全桌面；
- Windows 登录、锁屏和凭据桌面；
- Ctrl+Alt+Delete 安全注意序列；
- 受保护进程或其他隔离桌面。

本次不安装内核驱动，不修改 UAC 注册表设置，不关闭安全桌面，也不把整个 LanInputShare 联网进程提升为管理员权限。

## 方案选择

采用独立的高权限输入助手进程：

```text
主控输入
   │ TLS 局域网控制通道
   ▼
客户端 LanInputShare（普通权限，网络与 UI）
   │ 受限本机命名管道
   ▼
LanInputShareInputHelper（高权限，仅输入注入）
   │ SendInput
   ▼
Windows 默认交互桌面
```

不采用以下方案：

1. 整个客户端以管理员权限运行：实现简单，但会把监听端口、协议解析、剪贴板和文件传输全部放入高权限进程，攻击面过大。
2. 每次启动时 `runas`：会反复弹 UAC，不符合无人值守和开机自启需求。
3. Windows 服务直接调用 `SendInput`：服务位于 Session 0，不能直接控制用户的交互桌面；仍需额外的会话内助手。
4. 虚拟 HID 驱动：最接近物理设备，但需要驱动开发、签名、安装和维护，超出当前个人局域网工具的必要范围。

## 组件设计

### 输入助手

新增最小化入口和独立打包产物 `LanInputShareInputHelper.exe`。助手只包含：

- 当前会话识别；
- 本机命名管道服务；
- 客户端身份校验；
- 输入事件解码、边界校验和 `SendInput` 注入；
- 心跳、版本握手、按键释放和安全退出；
- 仅写入 Windows 事件日志或受限本地日志的必要诊断。

助手不读取 LanInputShare 网络配置，不监听 TCP 端口，不访问剪贴板和文件，不显示主窗口或托盘图标，也不接受任意命令、路径或可执行程序参数。

### 安装与启动

客户端界面增加“增强控制”状态和操作按钮：

- `未安装`：可点击“启用增强控制”；
- `正在运行`：版本和身份校验通过；
- `需要修复`：助手缺失、版本不一致或计划任务异常；
- `暂不可用`：助手本次连接失败，输入已降级；
- `已禁用`：用户主动移除。

首次启用时，主程序通过 `runas` 启动一次性安装动作。安装动作：

1. 将助手复制到管理员可写、普通用户不可修改的 `%ProgramFiles%\LanInputShare`；
2. 记录获准连接的主程序 SHA-256、标准化路径、当前用户 SID 和协议版本；
3. 创建属于当前用户、`InteractiveToken`、`RunLevel=Highest` 的登录计划任务；
4. 立即启动助手并等待主程序完成状态握手。

计划任务始终指向 `%ProgramFiles%` 中受保护的助手，绝不指向桌面、下载目录或其他普通用户可替换的位置。升级导致主程序或助手哈希变化时，必须再次经过一次 UAC 修复授权。禁用或卸载助手同样通过明确的管理员操作完成。

### 本机通信与授权

使用按 Windows 用户 SID 和会话 ID 区分的命名管道。管道 ACL 只允许对应用户和 SYSTEM 连接，但 ACL 不是唯一校验。

助手接受连接后还必须：

1. 使用 `GetNamedPipeClientProcessId` 取得真实客户端 PID；
2. 校验进程位于相同交互会话，且进程令牌用户 SID 与安装记录一致；
3. 读取该 PID 的规范化映像路径并计算文件 SHA-256；
4. 同时匹配安装时批准的路径、哈希和协议版本；
5. 任一条件不符时立即断开并记录不含敏感信息的拒绝原因。

本机协议采用长度前缀帧，只允许固定消息类型：`hello`、`input`、`release_all`、`ping` 和 `shutdown_if_idle`。所有字段设定大小、坐标、频率和枚举范围，未知字段或过大帧按协议错误断开。助手不提供通用进程启动、文件访问、注册表修改或 shell 执行能力。

### 输入路由与降级

客户端接收到远端输入后：

1. 助手在线且验证通过时，将输入发送给助手，不再由普通进程重复注入；
2. 助手未安装或不可用时，继续使用现有 `Win32InputInjector`，保证普通窗口仍可控制；
3. 助手连接中断时，双方立即释放已按下的按键和鼠标按钮，避免卡键；
4. 主界面更新为“增强控制暂不可用”，但不主动断开局域网控制会话；
5. 后台有限退避重连助手，成功后自动恢复增强控制。

助手只在默认交互桌面工作。检测到输入桌面不是 `Default` 时，不尝试绕过安全桌面；客户端向主控报告“客户端处于安全桌面，远程输入暂停”，回到默认桌面后自动恢复。

## 界面与用户提示

增强控制设置只在客户端角色下显示。界面需明确区分：

- “管理员窗口”：启用助手后可以控制；
- “UAC 安全桌面”：仍需客户端本地确认；
- “首次启用”：需要一次管理员授权；
- “日常运行”：计划任务自动启动，不重复弹 UAC。

如果当前前台窗口完整性高于输入执行进程，客户端应向主控返回结构化状态。主控状态栏显示原因，避免用户只看到鼠标不动却不知道为什么。

## 生命周期与更新

- 助手按用户登录启动，在相同交互会话运行；不创建 Session 0 服务。
- 主程序退出时助手可以保持空闲，供下一次启动复用；无连接时不注入任何输入。
- 助手崩溃不会导致主程序退出；主程序降级并重连。
- 主程序崩溃或网络断开时，助手通过心跳超时执行 `release_all`。
- 升级前停止旧助手；安装新版本并更新批准哈希后再启动。
- 多个 Windows 用户或远程桌面会话分别安装、启动并使用独立管道，禁止跨会话注入。

## 测试与验收

### 自动测试

- 安装命令和计划任务参数使用精确引用，不允许 shell 插值；
- 安装目标必须位于 `%ProgramFiles%\LanInputShare`；
- 管道 ACL、用户 SID、会话、路径、SHA-256 和协议版本逐项拒绝测试；
- 非法类型、越界字段、过大帧、重放握手和连接中断测试；
- 助手在线时不发生普通进程重复注入；
- 助手退出、版本不匹配和心跳超时均释放按键并安全降级；
- 原有输入、剪贴板、文件传输和重连测试保持通过。

### Windows 打包与双机验收

1. 普通记事本、浏览器和资源管理器可正常跨屏控制；
2. 高权限任务管理器和管理员命令行可移动、点击和输入；
3. UAC 安全桌面显示明确暂停提示，客户端本地确认后自动恢复；
4. 主程序正常退出、强制结束和重启后均可重新连接助手；
5. 助手正常退出、强制结束和登录后自动启动均可恢复；
6. 大文件传输期间键鼠控制仍保持现有 QoS；
7. 主控和客户端普通程序保持中等完整性，只有助手为高完整性；
8. 发布包记录主程序和助手 SHA-256，两台设备部署内容一致。

## 完成标准

- 用户只需在客户端首次启用或升级修复时确认 UAC；
- 日常启动不弹授权，增强控制状态在界面可见；
- 实机确认普通桌面上的高权限任务管理器可由主控操作；
- 安全桌面不被误报为可控制，并能在返回默认桌面后自动恢复；
- 不降低当前 TLS 配对、重连、剪贴板和文件传输的安全性与稳定性；
- 全部自动检查、打包运行测试和双机生命周期测试通过后才替换现有版本。
